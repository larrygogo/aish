## 2. 设计决策

### D1 — Layout 改 z-stack（relative + absolute）

**当前**：body 是 vertical flex_col (header / meta / preview / button)
**改后**：body 是 `relative` 容器，含两个 absolute 子层
- 底层：preview（满铺，相对父级 size_full）
- 顶层：bottom gradient scrim + 文字 overlay（absolute bottom_0 + inset_x_0）

**GPUI API**：
- `div().relative()` 父容器
- `.absolute().bottom_0().left_0().right_0().h(px(N))` 子层定位
- preview 走 `.absolute().inset_0()` 满铺

### D2 — preview 视觉调整

| 项 | M36 当前 | M36.1 改后 |
|---|---|---|
| 字体色 | `muted_foreground` #8b8d97 | **保持** muted_fg（作背景仍要 dim，让 overlay 抓眼） |
| 字号 | 10px | **保持** 10px |
| padding | px_2 py_2（占位框 inner） | **去掉** — 让 cells 满铺到卡边 |
| 高度 | ~120px 占位 | **整卡 size_full**（满铺） |

**保留 dim 而非提亮的理由**：Netflix cover art 也比 metadata 略 dim，让 metadata
站出来；如果 preview 提亮，文字 overlay 反而要更重 backdrop。维持 dim + 中等
gradient = 最 balanced。

### D3 — Bottom gradient scrim

**实现**：absolute div 覆盖卡片下方 ~45% 区，linear_gradient 从
`transparent` (top) → `card` color (#101113) (bottom)。

```rust
.bg(linear_gradient(
    180.0,
    linear_color_stop(card_bg.opacity(0.0), 0.0),   // top transparent
    linear_color_stop(card_bg, 1.0),                 // bottom solid card
))
.h(percent(45.0))   // 占卡片下 45%
.absolute().bottom_0().left_0().right_0()
```

**为什么 45%**：太短（30%）文字下边缘"飘"在 preview 上不稳；太长（60%）preview
看不清下半段。45% 是 Netflix / Spotify 实测的甜点。

**alt 对比**：
- A. ❌ solid 半透明黑色 panel（如 black.opacity(0.7)）：缺渐进过渡，硬切
- B. ❌ backdrop blur：GPUI 不支持 blur
- C. ✅ linear gradient transparent → card_bg：经典手法，GPUI 原生支持

### D4 — 文字 overlay 内容与位置

**结构**（自下而上）：
```
absolute bottom_0 left_0 right_0
  padding px_3 py_3
  flex_col gap_1
    row1: phase dot (6px) + Title3 host_label + Code tmux chip
    row2: Code user@host:port + Caption "刚刚 active"
```

**字体 color/weight 选择**：
- host_label：Title3 (14/600) + `foreground` #f4f5f8 高对比白
- user@host:port：Code (13/400) + `secondary_foreground` #c8cacf 略 dim
- 时长：Caption (12/400) + `muted_foreground` #8b8d97 最 dim

→ 三阶 hierarchy 立明。原 M36 用 dim 单调；poster 风要 contrast 拉开。

### D5 — 删 Attach button + 整卡 click 保留

**删**：
- HomeView.attach_buttons HashMap 字段
- attach_buttons 的 retain / ensure 逻辑
- render Phase B 内 attach button 渲染分支

**保留**：
- handle_active_card_click 方法（4 phase 分流逻辑不变）
- CardEntity.on_press 注册整卡 click（已有）

**已确认对齐用户诉求**：用户说"点击卡片本身就可以进入" → 不需要 button。

### D6 — 4 phase 兜底重设计（适配 poster 风）

| Phase | 当前 | M36.1 改后 |
|---|---|---|
| ShowCells | 占位框 + cells dim | **整卡 cells dim + bottom scrim + overlay 文字**（核心 poster 风） |
| WaitingForOutput | 占位框 + "等待输出..." 中央 | **整卡 muted secondary bg + "等待输出..." 中央 + overlay 文字**（poster 但 preview 是 placeholder 风） |
| Loading | 占位框 + Loader icon | **整卡 Loader 中央 + overlay 文字** |
| Disconnected | 占位框 + AlertTriangle + destructive 5% bg | **整卡 destructive.opacity(0.08) 平铺 + AlertTriangle 居中 + overlay 文字**（错误也用 poster 风一致） |

→ 4 phase 视觉结构一致（底层 + scrim + overlay），只差底层内容。

## 5. Self-Review

### 5.1 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| GPUI absolute + linear_gradient 在 z-stack 内交互未实测 | 中 | M35.1 D1 已验证 gradient 单独可行；absolute 是 GPUI 基础 API；T2 实施时若 fail 可退化 D3-alt（solid card.opacity(0.85) panel） |
| preview cells 满铺后 cursor █ 与卡片边界对齐丑 | 低 | preview cells 行高 px(10) × 行数 = ~120px；卡片高度 ~180px；可见行数自动适配 |
| 文字 overlay 与 preview 末尾几行 cell 视觉混叠 | 中 | gradient 45% 覆盖 + scrim color = card_bg，preview 在 scrim 区会被遮，不冲突 |
| Disconnected phase 用 destructive 平铺，scrim 是 card_bg 颜色，视觉不协调 | 中 | T3 实施时可微调 — Disconnected scrim 也用 destructive.opacity 渐变（保持错误语义） |
| 整卡 click 区域因 absolute layout 变化失效 | 低 | CardEntity.on_press 注册在 outer，z-stack 是 body 内部，click 区不变 |

### 5.2 回退预案

每 task 独立 commit：
- T2 视觉不好 → revert，回 M36 vertical stack 结构
- T1 删 button 后用户反悔 → revert T1，restore HashMap

### 5.3 Cross-component 检查

- ✅ sidebar 不影响
- ✅ saved 卡（vertical layout）不动
- ✅ tab system 不影响
- ✅ home empty / error state 不动
- ⚠️ preview pure-fn (home_preview.rs) 不动 — 但 ShowCells 渲染的 padding 处理点需要从渲染端去 px_2 py_2

### 5.4 Pixel budget

- T1 删 button：每卡 -32px (button height + gap) + -1 列 width 占用
- T2 preview 改满铺：净 +0（占满后被 scrim 半盖）
- T2 overlay 文字：在 scrim 区，与 preview 不挤
- T3 不改 pixel budget

**净结果**：卡片视觉密度提升（preview 占比从 ~40% → ~100% 视觉），信息密度持平。
