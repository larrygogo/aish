# aish App Icon 设计方案（M10）

**日期**：2026-05-09  
**状态**：✅ 已完成实现

---

## 1. 需求分析

| 维度 | 分析结果 |
|------|---------|
| **使用场景** | 跨平台应用图标（macOS Dock / Windows 任务栏 / Linux 桌面） |
| **核心概念** | `>` = SSH 终端提示符；`_` = AI 光标（补全/思考中）；合读 `>_` = AI Shell |
| **视觉风格** | 终端像素风：黑底 `#000000` + 终端绿 `#00FF41` + CRT 磷光辉光 + 扫描线纹理 |
| **跨平台格式需求** | macOS `.icns`（7 尺寸）/ Windows `.ico`（6 尺寸）/ Linux PNG 套装 |
| **设计目标** | 在小尺寸（16px）至大尺寸（1024px）上都清晰可识别，传达"AI 驱动的 SSH 终端"主题 |

---

## 2. SVG 设计规格

### 2.1 整体参数

```
viewBox: 64×64  （逻辑坐标）
物理尺寸: 64×64 px （渲染后）
像素映射: 1 SVG 单位 = 3×3 px （当输出 64px 时）
```

### 2.2 色彩

| 元素 | 颜色 | 用途 |
|------|------|------|
| 背景 | `#000000` | 纯黑，CRT 屏幕背景 |
| 主符号 | `#00FF41` | 经典终端绿（磷光） |
| 辉光滤镜 | `feGaussianBlur 1.4` | 模拟 CRT 磷光泛光 |
| 扫描线 | 半透明黑 `fill-opacity="0.12"` | 每 2px 高度一条 |

### 2.3 符号结构

**">" 箭头**（5列×9行，菱形指向右）
- 起点：`(14, 18)`
- 每像素宽度：3 SVG 单位
- 行高：3 SVG 单位
- 构成：像素化的右向菱形，尖端指向右侧

**"_" 光标**（6列×1行）
- 起点：`(32, 43)` 与 ">" 底行齐平
- 代表"AI 正在输入或思考"
- 宽度：18 SVG 单位（6 个像素）

### 2.4 特殊效果

1. **CRT 磨光辉光** — 使用 SVG `<filter>` 和 `<feGaussianBlur>`，参数 `stdDeviation="1.4"`
   - 目的：模拟老旧 CRT 屏幕的磷光溢出
   - 应用于：`#00FF41` 主符号

2. **扫描线纹理** — 通过 `<pattern>` 在整个背景上覆盖水平线
   - 参数：每 2px 高度一条，半透明（12% 不透明度）
   - 目的：增强 CRT 视觉风格

3. **圆角背景** — 背景矩形 `rx="10" ry="10"`
   - 目的：现代应用图标风格（避免尖锐角，macOS 风格）

## 3. 跨尺寸适配策略

由于 SVG 是矢量的，不同尺寸均自动缩放：

| PNG 尺寸 | 用途 | 包含格式 |
|----------|------|---------|
| 16×16 | 文件图标、菜单 | PNG, ICO, ICNS |
| 32×32 | 系统托盘 | PNG, ICO, ICNS |
| 48×48 | Windows 标准（可选）| PNG, ICO |
| 64×64 | 中等显示 | PNG, ICO, ICNS |
| 128×128 | 高清显示 | PNG, ICNS |
| 256×256 | Retina/双倍密度 | PNG, ICNS |
| 512×512 | 超高清、应用商店 | PNG, ICNS |
| 1024×1024 | 源档参考 | PNG |

## 4. 设计决策记录

### 4.1 为什么选择 `>_`？

- `>` 是 Unix/Linux/SSH shell 的标志性提示符，用户一眼即认出
- `_` 在终端中代表"光标"，可表示 AI 在"思考"或"等待输入"
- 合读 `>_` 直观传达 "AI Shell" 主题
- 像素化风格匹配终端文化，容易在小尺寸上保持清晰度

### 4.2 为什么使用 CRT 风格？

- aish 的核心是"远程终端操作"，视觉风格应与内容一致
- 终端绿 + 黑底 + 磨光 + 扫描线，文化认同度高（黑客/开发者文化）
- 在像素风基础上加效果（磨光、扫描线），避免过时感，增加现代感

### 4.3 为什么是纯 SVG 单一真相来源？

- **一致性**：所有尺寸和格式均由同一 SVG 生成，无手工调整，避免视觉漂移
- **可维护性**：未来修改设计时，仅需改 SVG，自动重新生成所有格式
- **跨平台**：无平台差异，Windows/macOS/Linux 看到完全相同的设计

## 5. 技术约束

1. **SVG 兼容性**
   - 必须支持 resvg (WASM 或 Rust) 的完整 SVG 1.1 特性
   - 避免仅 Chromium 支持的扩展
   - 滤镜使用标准 `feGaussianBlur` 和 `feMerge`

2. **渲染精度**
   - 16px 及以下尺寸必须保证 `>` 和 `_` 能正确识别
   - 不能使用小于 1px 的线条（会在小尺寸上消失）

3. **文件体积**
   - 单个 PNG：最小 360 bytes（16×16），最大 ~90 KB（1024×1024）
   - ICO：~ 370 KB（6 尺寸）
   - ICNS：~ 132 KB（7 尺寸）
   - 总体 < 600 KB，可接受

4. **平台特定要求**
   - **Windows**：ICO 需包含 16, 32, 48, 64, 128, 256 六个尺寸
   - **macOS**：ICNS 需包含 16, 32, 64, 128, 256, 512, 1024（共 7 个）；通过 `CFBundleIconFile` 在 Info.plist 中引用
   - **Linux**：`.desktop` 文件指定 Icon 键，系统在 icon theme 中查找 `aish.png`

## 6. 验收标准

### 6.1 视觉验收

- [ ] SVG 在浏览器预览，验证色彩、滤镜、扫描线效果符合设计
- [ ] 16×16 PNG 能清晰显示 `>` 和 `_`（不糊不缺失像素）
- [ ] 1024×1024 PNG 质量高、无锯齿边缘
- [ ] Windows 资源管理器显示图标正确，无失真
- [ ] macOS Dock 显示图标正确，包括 Retina 高清
- [ ] Linux 文件管理器显示图标正确

### 6.2 技术验收

- [ ] ICO 文件魔法字节正确：`00 00 01 00`
- [ ] ICNS 文件魔法字节正确：`69 63 6e 73`（即 ASCII "icns"）
- [ ] 所有 PNG 文件大小 > 0，格式有效（PNG 头 `89 50 4E 47`）
- [ ] Windows build.rs 编译无错误，EXE 成功嵌入 ICO
- [ ] cargo fmt + clippy 无警告
- [ ] cargo test 全过

## 7. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| SVG 渲染工具（resvg）不支持某个滤镜 | 低 | 图标效果缺失 | 使用成熟的 resvg 0.47+ |
| 小尺寸（16px）上字符不清晰 | 中 | 用户无法识别 | 逐级查看，手工调整像素偏移 |
| macOS ICNS 生成工具兼容性问题 | 低 | 图标不显示 | 用 @fiahfy/icns，前有测试 |
| Linux icon theme 查找失败 | 低 | Linux 上无图标 | .desktop 文件指定绝对路径备选 |

## 8. 后续优化空间

1. **动画图标**：如果未来需要，可在 SVG 中加 `<animate>`，部分平台支持
2. **暗色/亮色主题适配**：当前仅一种配色；可扩展为 light variant
3. **局部高分辨率处理**：超大尺寸（2048px+）可能需要手工优化扫描线间距
4. **Logo 变种**：可基于同一 SVG 衍生"仅 > 符号"等简化版本
